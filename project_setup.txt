1. PREREQUISITES
----------------------------------------------------------------

For Web + Backend Development:
  - Node.js v20 or higher        https://nodejs.org
  - npm v9 or higher             (bundled with Node.js)
  - PostgreSQL v14 or higher     https://www.postgresql.org

For Android Development:

  - Java 17 (set in kotlinOptions + compileOptions)
  - Google Services / Firebase project (optional, for FCM push)
  - Physical device or emulator (API 26+)

2. QUICK-START (Replit / Cloud Environment)
----------------------------------------------------------------

If you are running this project on Replit, the DATABASE_URL
environment variable is pre-configured and PostgreSQL is
already available. No manual database setup is required.

Step 1 — Install backend dependencies (from project root):
  npm install

Step 2 — Install frontend dependencies:
  cd client && npm install && cd ..

Step 3 — Start the backend:
  node server/index.js
  → Listens on PORT env var (default 5000)
  → Schema auto-created; demo data seeded on startup

Step 4 — Start the frontend (separate terminal):
  cd client && npm run dev
  → Vite dev server on port 5173
  → Proxies /api/* to localhost:5000

Step 5 — Open browser:
  http://localhost:5173

Demo login credentials (auto-seeded):
  Admin:    admin@smartattend.edu   / Admin@123
  Teacher:  priya@smartattend.edu   / Teacher@123
  Student:  aarav@smartattend.edu   / Student@123

3. LOCAL SETUP (Non-Replit / On-Premises)
----------------------------------------------------------------

Step 1 — Clone the repository:
  git clone <repository-url>
  cd smart-attendance-system

Step 2 — Install backend dependencies:
  npm install

Step 3 — Install frontend dependencies:
  cd client && npm install && cd ..

Step 4 — Create and configure the PostgreSQL database:
  psql -U postgres -c "CREATE DATABASE smartattend;"

Step 5 — Set required environment variables:
  On Linux / macOS (add to ~/.bashrc or ~/.zshrc for persistence):
    export DATABASE_URL="postgresql://postgres:yourpassword@localhost:5432/smartattend"
    export JWT_SECRET="replace-with-a-strong-random-secret"
    export SESSION_SECRET="replace-with-another-random-secret"

  On Windows (PowerShell):
    $env:DATABASE_URL="postgresql://postgres:yourpassword@localhost:5432/smartattend"
    $env:JWT_SECRET="replace-with-a-strong-random-secret"
    $env:SESSION_SECRET="replace-with-another-random-secret"

  On Windows (Command Prompt):
    set DATABASE_URL=postgresql://postgres:yourpassword@localhost:5432/smartattend
    set JWT_SECRET=replace-with-a-strong-random-secret
    set SESSION_SECRET=replace-with-another-random-secret

Step 6 — Start the backend:
  node server/index.js
  Expected output:
    Database schema ready
    Seeding database...
    Database seeded successfully!
    SmartAttend API running on port 5000

Step 7 — Start the frontend (in a separate terminal):
  cd client && npm run dev
  Expected output:
    VITE v5.x  ready in xxx ms
    ➜  Local:   http://localhost:5173/

Step 8 — Open the app:
  http://localhost:5173

6. RUNNING IN PRODUCTION
----------------------------------------------------------------

Step 1 — Build the frontend:
  cd client && npm run build
  → Outputs static files to client/dist/

Step 2 — Configure environment variables on your server:
  DATABASE_URL, JWT_SECRET, SESSION_SECRET (see Section 4)
  Optionally: Firebase credentials

Step 3 — Serve using PM2 (recommended):
  npm install -g pm2
  pm2 start server/index.js --name smartattend
  pm2 save
  pm2 startup

Step 4 — Remove development-only code BEFORE deploying:
  a. Open server/db/database.js
     Remove all "DROP TABLE IF EXISTS" lines (~line 1–35)
     These lines wipe all data on every restart!
  b. Restrict CORS in server/index.js to your production domain
  c. Set NODE_ENV=production

Step 5 — (Optional) Nginx reverse proxy:
  server {
    listen 80;
    server_name yourdomain.com;
    location / {
      proxy_pass http://localhost:5000;
      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
    }
  }

Production build serves the React app from Express:
  The backend at port 5000 automatically serves client/dist/
  for all non-/api requests (static file serving is configured
  in server/index.js).

7. DATABASE — SCHEMA & SEEDING DETAILS
----------------------------------------------------------------

Schema Auto-Creation:
  The backend calls initDB() on startup (server/db/database.js).
  All tables are created if they do not exist.
  In development, DROP TABLE statements run first (data reset).

Tables Created:
  users, branches, classes, teachers, students, subjects,
  attendance_sessions, attendance, attendance_requests,
  notifications, anomaly_logs, audit_logs, password_reset_otps

Seeded Demo Data (server/db/seed.js):
  - 1 Admin user
  - 2 Teachers (priya, rajan)
  - 1 Branch (Engineering)
  - 1 Class (CSE 3rd Year, Section A)
  - 6 Subjects (assigned to teachers)
  - 6 Students (enrolled in class)
  - ~30 days of historical attendance records per student

Re-seeding:
  Data is re-seeded every time the backend restarts (in dev).
  To disable seeding, comment out the seed.js call in index.js.

8. ANDROID SETUP
----------------------------------------------------------------

Android App Launch Flow (v2.3+):
  SplashActivity (LAUNCHER)
    ↓ 2-second animated entrance
    ├── token in DataStore → MainActivity (role-based nav)
    └── no token           → HomeActivity (role selection)
                               ↓ card tap
                             LoginActivity

  After login, the user lands in MainActivity. Logout is
  available via the overflow menu (⋮) in the toolbar.

Step 1 — Open the project:
  - Launch Android Studio
  - Select "Open an Existing Project"
  - Navigate to the android/ folder in the cloned repo
  - Wait for Gradle sync to complete

Step 2 — Sync Gradle:
  - Android Studio will prompt to sync. Click "Sync Now".
  - If errors appear, verify Java 17 is the active JDK:
    File → Project Structure → SDK Location → Gradle JDK → 17

Step 3 — Configure the backend URL:
  Open android/app/build.gradle:
    debug build type:
      buildConfigField "String", "BASE_URL",
        '"http://10.0.2.2:5000/api/"'
      (10.0.2.2 is the Android emulator's alias for localhost)

    release build type:
      buildConfigField "String", "BASE_URL",
        '"https://your-production-domain.com/api/"'

  After changing, click "Sync Project with Gradle Files".

Step 4 — Firebase setup (optional, for push notifications):
  a. Go to https://console.firebase.google.com
  b. Create a new project (or use an existing one)
  c. Add an Android app with package name: com.smartattend
  d. Download google-services.json
  e. Place it in android/app/google-services.json
  f. In the Firebase Console, enable Cloud Messaging (FCM)
  g. Copy Firebase credentials to backend environment variables:
       FIREBASE_PROJECT_ID
       FIREBASE_CLIENT_EMAIL
       FIREBASE_PRIVATE_KEY
  h. Sync Gradle in Android Studio

  NOTE: If you skip this step, the app still works fully.
  Push notifications require Firebase; in-app notifications do not.

Step 5 — Run on emulator:
  a. Tools → AVD Manager → Create Virtual Device
  b. Select a phone profile (e.g., Pixel 6)
  c. Choose API level 26 or higher (Android 8.0+)
  d. Start the emulator
  e. Click the green Run button (Shift+F10)

Step 6 — Run on physical device:
  a. Enable Developer Options on the device:
     Settings → About Phone → tap Build Number 7 times
  b. Enable USB Debugging in Developer Options
  c. Connect device via USB
  d. Trust the computer when prompted
  e. Select your device from the device dropdown in Android Studio
  f. Click Run (Shift+F10)
  g. IMPORTANT: Change BASE_URL in debug build config to your
     machine's IP address (not 10.0.2.2):
     e.g., "http://192.168.1.100:5000/api/"
     Ensure your device and computer are on the same network.

Step 7 — Build a release APK:
  a. Build → Generate Signed Bundle / APK
  b. Select APK
  c. Create or provide a keystore file
  d. Enter keystore credentials
  e. Select "release" build variant
  f. Click Finish
  g. APK saved to: android/app/release/app-release.apk

10. TROUBLESHOOTING
----------------------------------------------------------------

Web / Backend:
  "Cannot find module 'express'" or similar:
    → Run: npm install (from project root)
    → Run: cd client && npm install

  "DATABASE_URL not set" or connection refused:
    → Set DATABASE_URL environment variable (Section 4)
    → Ensure PostgreSQL is running: pg_ctl status

  "JWT malformed" or 401 errors:
    → Clear localStorage in browser (DevTools → Application)
    → Log in again

  Face detection not working:
    → Use Chrome or Edge (WebGL + camera access required)
    → Allow camera permissions when prompted
    → Must use HTTPS or localhost (browser security requirement)

  API calls returning 404:
    → Verify Vite proxy is configured: client/vite.config.js
      Should proxy /api → http://localhost:5000
    → Verify backend is running on port 5000

Android:
  Gradle sync fails:
    → File → Invalidate Caches and Restart
    → Verify Java 17 is the Gradle JDK
    → Check internet connection for dependency download

  "Connection refused" on emulator:
    → BASE_URL must be http://10.0.2.2:5000/api/ (not localhost)
    → Verify backend is running before launching app

  "Connection refused" on physical device:
    → Change BASE_URL to your machine's local IP (e.g., 192.168.x.x)
    → Both device and computer must be on the same Wi-Fi network
    → Disable firewall temporarily if still failing

  App crashes on launch (Resources$NotFoundException):
    → Check Logcat for the exact missing resource name
    → Confirm all vector drawables referenced in layouts exist
      under android/app/src/main/res/drawable/
    → Confirm all color references exist in res/values/colors.xml
      or res/color/ (e.g., bottom_nav_color.xml)
    → After v2.3, all standard drawables and colors are included

  App launches but skips splash screen / shows blank:
    → Verify SplashActivity has the MAIN + LAUNCHER intent-filter
      in AndroidManifest.xml (fixed in v2.3)
    → Verify SplashActivity is android:exported="true"

  Can't find logout button:
    → Logout is in the toolbar overflow menu (⋮ icon, top-right)
      inside MainActivity (added in v2.3)

  Camera / location permission denied:
    → Grant permissions manually in device Settings → Apps
    → SmartAttend → Permissions

11. DEVELOPMENT WORKFLOW TIPS
----------------------------------------------------------------

API Testing (curl examples):

  Login:
    curl -X POST http://localhost:5000/api/auth/login \
      -H "Content-Type: application/json" \
      -d '{"email":"admin@smartattend.edu","password":"Admin@123"}'

  Get profile (replace TOKEN):
    curl http://localhost:5000/api/auth/me \
      -H "Authorization: Bearer TOKEN"

  Get admin stats:
    curl http://localhost:5000/api/admin/stats \
      -H "Authorization: Bearer TOKEN"

Adding a New API Endpoint:
  1. Add the route in the appropriate file under server/routes/
  2. Add the corresponding Retrofit interface method in
     android/…/data/api/ApiService.kt
  3. Add repository method in the corresponding Repository.kt
  4. Update the ViewModel and Fragment/Activity

Resetting the Database:
  Simply restart the backend. The DROP TABLE + seed runs again.
  All data returns to the seeded demo state.

Checking OTP Codes:
  OTPs are printed to the backend console (stdout):
    "OTP for <email>: 123456"
  Copy this value to use in the forgot-password flow.

Android Debug Tips:
  - Use Logcat (Android Studio) filtered to "com.smartattend"
    to see all app logs including Hilt/DI errors, Retrofit errors,
    and navigation issues
  - The AuthInterceptor logs are visible when
    HttpLoggingInterceptor.Level.BODY is set (debug builds only)
  - DataStore is read asynchronously; SplashActivity uses
    TokenManager.getToken() (runBlocking) for the initial check

Audit Logs Test (Admin):

Profile Test:

  3. Tap Edit Profile → change name → Save
